# TauHorse — начать здесь

Проект подготовлен как переносимый production-пакет: Linux + Docker Compose. На сервер не нужно отдельно ставить Node.js, PostgreSQL, Nginx, Prisma или Certbot — сервисы запускаются контейнерами.

## Домашний сервер — первый production

До запуска проверьте инфраструктуру:

1. У домашнего подключения есть публичный IPv4 и входящие подключения не блокируются CGNAT провайдера.
2. На роутере TCP 80 и 443 проброшены на постоянный локальный IP Linux-сервера.
3. DNS A-запись `tauhorse.ru` указывает на публичный IPv4 дома.
4. Если внешний IP динамический, до публикации нужен способ автоматически обновлять DNS при его смене.
5. Сервер работает круглосуточно; желательно проводное подключение и ИБП.
6. Резервные копии нужно регулярно выносить с этого компьютера во внешнее приватное хранилище.

После распаковки проекта на Ubuntu/Debian/AlmaLinux/Rocky:

```bash
cd /opt/tauhorse
sudo ./install.sh
```

Скрипт установит Docker, если его нет, создаст production `.env`, сгенерирует секреты, проверит конфигурацию, соберёт приложение, получит сертификат Let's Encrypt и поднимет PostgreSQL + Nuxt + Nginx + Certbot + backup.

SMTP можно пропустить в мастере. Тогда магазин запустится, но подтверждение email, восстановление пароля, письма по заказам и рассылки не будут отправляться, пока SMTP не будет настроен.

После подключения SMTP:

```bash
sudo ./smtp-test.sh
sudo ./update.sh
```

## Обычные команды

```bash
sudo ./status.sh       # контейнеры
sudo ./logs.sh         # логи приложения и nginx
sudo ./update.sh       # пересобрать и обновить production
sudo ./backup.sh       # полный export БД + media + production env
```

Архив из `./backup.sh` содержит секреты. Храните его как пароль и не публикуйте.

## Перенос на другой сервер

На старом:

```bash
sudo ./backup.sh
```

На новом загрузите исходники TauHorse и export-архив, затем:

```bash
sudo ./restore.sh /path/to/tauhorse_YYYYMMDD_HHMMSS.tar.gz
```

## Перед реальными продажами

Обязательно пройдите `PRODUCTION_CHECKLIST.md`. В частности, до приёма реальных расчётов нужно решить вопрос ККТ/чеков для фактической схемы оплаты, а до обработки персональных данных — выполнить организационные обязанности оператора персональных данных.
