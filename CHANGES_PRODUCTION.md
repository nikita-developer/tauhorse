# TauHorse — production changes

Дата подготовки: 18.10.2026

Этот пакет подготовлен как production-кандидат интернет-магазина TauHorse.

## Что изменено

- Брендинг сайта переведён на `TauHorse`; старое пользовательское название магазина удалено.
- Добавлен финальный логотип TauHorse для шапки, футера, favicon и Open Graph.
- Контакты и реквизиты заменены на реальные данные продавца и контактного лица.
- Каталог и карточка товара сохраняют последние UX-правки: мобильный фильтр, единый select, диапазон цены, стабильная фильтрация, галерея со свайпом/стрелками и компактный адаптив.
- Исправлено поведение диапазона цены при ручном вводе значения вне фактического диапазона каталога.
- Статус нового заказа называется «Получен»; после связи с покупателем используется внутренний статус «Подтверждён».
- Гостевой заказ остаётся доступен без обязательной регистрации.
- Обновлены страницы доставки, возврата, оферты, реквизитов, персональных данных, cookies и маркетингового согласия под фактическую модель магазина.
- SMTP можно подключить позже: production-конфигурация допускает запуск без почтового транспорта и строго проверяет частично заполненные SMTP-настройки.
- Добавлены SEO/composable, canonical, Open Graph, Twitter cards, sitemap.xml, robots.txt и Product/Offer/FAQ structured data.
- Для Nginx включены gzip и длительное кэширование версионированной статики/брендовых ассетов.
- Зависимости npm зафиксированы точными версиями; Docker использует `npm ci`.
- Production-образы Docker закреплены на конкретных версиях.
- Документация переписана под домашний Linux-сервер как первый production-хост и дальнейший перенос на VPS.

## Что нужно сделать перед публичным запуском

1. Настроить `tauhorse.ru` на публичный IP сервера и убедиться, что провайдер не использует CGNAT для входящих подключений.
2. Пробросить TCP 80/443 на production-сервер и ограничить остальные внешние порты.
3. Решить вопрос с ККТ/кассовыми чеками для выбранных способов расчёта до приёма реальных платежей.
4. Проверить обязанности оператора персональных данных и уведомление Роскомнадзора; production-БД с персональными данными граждан РФ должна соответствовать требованиям локализации.
5. Подключить SMTP (планируется Unisender Go), настроить SPF/DKIM/DMARC и выполнить тестовые служебные и маркетинговые отправки.
6. Настроить внешнюю резервную копию вне самого домашнего сервера.
7. После публикации прогнать Lighthouse/PageSpeed по реальному HTTPS-домену и проверить Core Web Vitals на мобильной сети.
8. Сделать контрольный заказ как гость и как зарегистрированный пользователь, проверить письма, смену статусов, отмену, возврат и админ-процесс.
